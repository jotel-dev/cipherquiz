## Typography, color, backgrounds and motion

- [Google Fonts: Manrope](https://fonts.google.com/specimen/Manrope) and [Space Grotesk](https://fonts.google.com/specimen/Space+Grotesk): specimen pages opened but yielded no readable web-reader content. Both fonts were loaded through the Google Fonts stylesheet and inspected in the actual Chrome-rendered product. Manrope provides a quiet interface; Space Grotesk gives headings and scores a more individual voice. Georgia italic adds a limited editorial accent without another download.
- [Typescale](https://typescale.com/): inspected its responsive base-size/ratio and body/heading controls. Implemented a 16px, 1.25 major-third scale with fluid heading endpoints and optical small labels in `tokens.css`.
- [Coolors supplied palette](https://coolors.co/faf9f6-ffffff-17151d-6d35e8-eae6f2): web reader returned 403/inaccessible; Chrome eventually rendered the five specified swatches and hex labels. Preserved those exact colors. Added muted green, ochre and blue category tints and darkened secondary text to `#655E70` after actual contrast testing.
- [easings.net](https://easings.net/): inspected its easing overview and easeOutCubic reference. Implemented `cubic-bezier(0.33, 1, 0.68, 1)` for reveals/progress. Hover/press is short; there is no animated backdrop or perpetual card movement.
- [60fps Design](https://60fps.design/): inspected its public app/motion/snippet catalog. Used state-oriented motion as a review criterion: show selection and progress quickly; avoid animation that keeps players waiting. No private video library or app clip is claimed as reviewed.
- [PatternCraft](https://patterncraft.fun/) and [BG by Ibelick](https://bg.ibelick.com/): inspected the CSS pattern/background collections. A low-contrast radial-dot grid is confined to the hero placeholder. The rest of the page uses flat warm surfaces. No package or heavy background renderer was added.
- [CSS Loaders](https://css-loaders.com/): inspected the lightweight single-element loader categories. Implemented a CSS border spinner and opacity skeleton with descriptive status text for wallet requests, local calculation/reveal and API checks. Reduced motion shows a static indicator.

## Checklist Design review

The web reader returned no usable content. Chrome successfully loaded the homepage and the actual [web onboarding](https://www.checklist.design/web-app/onboarding), [empty state](https://www.checklist.design/web-app/empty-state), [loading](https://www.checklist.design/design-system/loading), [input error](https://www.checklist.design/flows/showing-input-error) and [modal](https://www.checklist.design/design-system/modal) checklists.

Applied review points:

| Flow         | Result                                                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Onboarding   | No required account or wallet before first value; category and setup form a short path; one clear start action.                                   |
| Wallet       | Clear purpose, no-provider recovery, descriptive pending text, rejection recovery, supported-network guidance and disconnect.                     |
| Staking      | Simulation stated before the action; total returns include principal; credit value and zero-return tier are explicit; acknowledgment is required. |
| Loading      | Only pending work receives a spinner/status description; static category and fixture lists render immediately.                                    |
| Errors       | API retry, wallet retry, native required name constraints, invalid-route recovery and render-error recovery preserve a next step.                 |
| Empty states | Missing results/history explain why and lead directly to a first round; filtered lists have no-results handling.                                  |
| Dialogs      | Clear titles, specific action labels, accessible close controls, scrollable small-screen content and Radix focus management.                      |
| Mobile       | Seven requested widths tested; no page overflow; answer targets exceed 44px; round state and actions stay usable when scrolling.                  |

These checks guided implementation and browser verification. They are not a claim that Checklist Design performed an automated review of this repository.

## Reproducing the external visual review

`node apps/web/scripts/review-resources.mjs` uses installed Chrome to capture the public resources; optional names limit the run (for example `coolors checklist`). It writes to ignored `apps/web/.design-research/`. Initial blank captures were retried with client-rendering time before claiming a successful review. External captures are research evidence only and are not included in the production app or committed review screenshots.
